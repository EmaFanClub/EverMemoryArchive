## ADDED Requirements

### Requirement: 日程界面展示当前角色日程

系统 MUST 在角色侧栏的日程页签展示当前选中角色拥有的日程条目，并按单次日程、周期日程、关注会话和过时日程进行区分。

#### Scenario: 打开有日程的角色日程页签

- **WHEN** 用户在 Dashboard 选中一个已有日程的角色并打开日程页签
- **THEN** 系统 MUST 依次展示该角色的单次日程、周期日程、关注会话和过时日程分组
- **AND** 每个日程条目 MUST 展示任务类型、时间或周期、摘要或正文预览

#### Scenario: 打开没有日程的角色日程页签

- **WHEN** 用户在 Dashboard 选中一个没有对应分组日程的角色并打开日程页签
- **THEN** 系统 MUST 在空分组中展示无日程状态
- **AND** 系统 MUST NOT 展示其他角色的日程

### Requirement: 日程界面限制编辑范围

系统 MUST 允许用户编辑可编辑日程条目的文本内容、编辑可编辑单次日程的时间，并允许用户在确认后删除可编辑日程，但 MUST NOT 允许用户通过该界面修改周期、任务类型或目标会话。

#### Scenario: 编辑日程文本内容

- **WHEN** 用户修改一个可编辑日程条目的摘要或正文并保存
- **THEN** 系统 MUST 持久化新的文本内容
- **AND** 系统 MUST 保持该日程条目的周期、任务类型和目标会话不变

#### Scenario: 编辑单次日程时间

- **WHEN** 用户修改一个可编辑单次日程的时间并保存
- **THEN** 系统 MUST 校验时间符合有效的 `YYYY-MM-DD HH:mm:ss` 格式
- **AND** 系统 MUST 持久化新的单次日程时间
- **AND** 系统 MUST 保持该日程条目的周期、任务类型和目标会话不变

#### Scenario: 查看不可编辑时间字段

- **WHEN** 用户查看或编辑周期日程、关注会话或不可编辑日程条目
- **THEN** 系统 MUST 将时间、周期、任务类型和目标会话作为只读信息展示
- **AND** 系统 MUST NOT 提供修改这些字段的控件

#### Scenario: 删除可编辑日程

- **WHEN** 用户打开一个可编辑日程的详情并点击删除
- **THEN** 系统 MUST 在删除前展示确认弹窗
- **AND** 用户确认后系统 MUST 删除该日程
- **AND** 系统 MUST 从当前日程列表中移除该日程

#### Scenario: 禁止删除不可编辑日程

- **WHEN** 用户查看作息、关注会话或其他不可编辑日程
- **THEN** 系统 MUST NOT 展示删除入口
- **AND** 日程删除接口 MUST 拒绝删除不可编辑日程

#### Scenario: 查看没有可编辑文本的日程

- **WHEN** 用户查看作息或关注会话等没有用户可维护文本内容的日程
- **THEN** 系统 MUST 以只读方式展示该日程
- **AND** 系统 MUST NOT 展示无效的编辑入口

### Requirement: 记忆界面展示分层短期记忆

系统 MUST 在角色侧栏的记忆页签展示当前选中角色的年记、月记、日记和活动记忆。

#### Scenario: 打开有记忆的角色记忆页签

- **WHEN** 用户在 Dashboard 选中一个已有短期记忆的角色并打开记忆页签
- **THEN** 系统 MUST 展示年记、月记、日记和活动记忆分组
- **AND** 每个记忆条目 MUST 以简洁卡片展示日期、正文预览和可用的更新时间信息
- **AND** 活动记忆卡片 MUST 在左上角以胶囊标签展示当前成熟数据模型可表达的来源

#### Scenario: 打开没有记忆的角色记忆页签

- **WHEN** 用户在 Dashboard 选中一个没有短期记忆的角色并打开记忆页签
- **THEN** 系统 MUST 在每个空分组中展示无记忆状态
- **AND** 系统 MUST NOT 展示其他角色的记忆

### Requirement: 记忆界面支持编辑记忆正文

系统 MUST 允许用户编辑年记、月记、日记和活动记忆条目的正文内容，并允许用户在确认后删除记忆条目；编辑时 MUST 保持条目的归属、类型和日期不变。

#### Scenario: 编辑年记月记日记正文

- **WHEN** 用户打开一个年记、月记或日记条目的详情并修改正文后保存
- **THEN** 系统 MUST 持久化新的正文内容
- **AND** 系统 MUST 保持该条目的记忆类型、日期和角色归属不变

#### Scenario: 编辑活动记忆正文

- **WHEN** 用户打开一个活动记忆条目的详情并修改正文后保存
- **THEN** 系统 MUST 持久化新的正文内容
- **AND** 系统 MUST 保持该条目的记忆类型、日期、dayDate 和角色归属不变

#### Scenario: 保存空记忆正文

- **WHEN** 用户尝试保存空白的记忆正文
- **THEN** 系统 MUST 拒绝保存
- **AND** 系统 MUST 向用户展示可恢复的错误状态

#### Scenario: 删除记忆条目

- **WHEN** 用户打开一个记忆条目的详情并点击删除
- **THEN** 系统 MUST 在删除前展示确认弹窗
- **AND** 用户确认后系统 MUST 删除该记忆条目
- **AND** 系统 MUST 从当前记忆列表中移除该条目

### Requirement: 日程和记忆面板处理加载与错误状态

系统 MUST 在日程和记忆数据加载、保存失败或角色切换时提供明确且不会污染其他角色数据的状态反馈。

#### Scenario: 数据加载中

- **WHEN** 用户打开日程或记忆页签且数据请求尚未完成
- **THEN** 系统 MUST 展示加载状态
- **AND** 系统 MUST NOT 展示过期角色的数据作为当前角色数据

#### Scenario: 数据加载失败

- **WHEN** 日程或记忆数据加载失败
- **THEN** 系统 MUST 展示失败状态和重试入口
- **AND** 系统 MUST 保留用户继续切换其他页签的能力

#### Scenario: 保存失败

- **WHEN** 用户保存日程或记忆内容失败
- **THEN** 系统 MUST 展示错误状态
- **AND** 系统 MUST 保留用户未成功保存的编辑内容以便重试
