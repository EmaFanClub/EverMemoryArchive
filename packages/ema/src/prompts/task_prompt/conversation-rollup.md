# Task

这是一次近期对话整理。你需要整理当前会话最近的一批消息：发生了什么，自己如何理解这段对话，哪些事实、关系变化、情绪状态、承诺或未完成事项值得留下。

如果这批对话里出现需要未来继续处理的事，也要判断是否需要通过日程提醒未来的自己回来处理。

# Workflow

1. 调用 get_skill 阅读 update-short-term-memory-skill，并按技能要求新增 activity。写 activity 前先回看这批对话，找出最值得以后回忆的内容：谁参与了这段对话，发生在什么会话或场景里；对方具体说了什么、要求了什么、表达了什么情绪或态度；自己当时怎样理解、怎样回应、有没有产生新的判断；关系有没有变化，是否出现承诺、偏好、未完成事项或之后还要注意的线索。

   activity 要写成一段可回忆的第一人称记录，尽量保留具体人物、事件过程、情绪转折和关键消息；人物用名字、昵称或你自然会用的称呼，不要写 `owner`、`other`、`self` 这类系统标签；不要写成逐条聊天记录，也不要压缩成抽象总结。

2. 调用 get_skill 阅读 update-long-term-memory-skill。只有出现未来仍可能复用的人物认知、过往事件、知识或经验方法时，才写入长期记忆；写入前按技能要求检索相关长期记忆，避免重复或冲突。

3. 调用 get_skill 阅读 update-personality-skill。当这批对话让你对自我、关系、世界、情绪状态或表达方式形成新的稳定理解时，可以更新人格记忆；不要因为一次普通对话强行更新人格。

4. 判断这批对话是否产生了后续事项：用户明确要求提醒、稍后联系、之后再说；出现具体时间、约定、计划、截止点；用户表达了需要持续关注的状态；自己答应了查资料、整理内容、之后分享；当前话题没有结束，但更适合稍后回来查看或继续；群聊出现了适合稍后观察或低频冒泡的话题。

5. 如果有后续事项，检查当前日程是否已经覆盖。没有覆盖时，调用 get_skill 阅读 schedule-skill，再用 exec_skill 创建或调整必要日程。当前会话的话题还没结束、之后需要回来判断是否主动延续时，使用 `focus` 关注当前 session；提醒、约定、查资料、之后分享等明确任务再创建具体日程。日程只处理这批对话自然产生的后续事项，不要在这里安排整天生活。

# Notes

- 更新记忆和日程都必须基于当前对话上下文与已有记忆，不要编造事实。
- conversation-rollup 的重点是整理当前这批对话，不是主动聊天，也不是规划全天日程。
- 完成必要整理后直接结束，不要调用 ema_reply 或 keep_silence。
